1. INTRODUCTION                                         *sagefs-introduction*

sagefs.nvim is the Neovim frontend for SageFs, a live F# development server
that eliminates the edit-build-run cycle. SageFs provides sub-second hot
reload, live unit testing, code coverage, and an MCP server for AI agents.

This plugin connects Neovim to the running SageFs daemon, providing:
- Cell evaluation with inline results
- Live test state with gutter signs
- Code coverage with gutter annotations
- Session management (multi-project)
- Hot reload controls, and what the last save did (see |sagefs-reload-truth|)
- Debugging a failing test with nvim-dap (see |:SageFsDebugTest|)
- SSE live updates from the daemon

Architecture: pure Lua modules with zero vim API dependencies (fully
testable under busted), plus an integration layer in init.lua that wires
pure modules to keymaps, extmarks, autocmds, and curl-based HTTP.
The runners print their own counts (see TESTING.md); I keep numbers out of
this file because they go stale with every release. |:SageFsHelp| lists the
commands that are registered right now.

2. QUICKSTART                                            *sagefs-quickstart*

1. Install SageFs: >
     dotnet tool install -g sagefs
<
2. Add the plugin (lazy.nvim): >lua
     { "WillEhrendreich/sagefs.nvim", config = true }
<
3. Open your F# project: >
     cd ~/myproject
     nvim MyScript.fsx
<
4. Start the daemon (auto-discovers .sln/.fsproj): >vim
     :SageFsStart
<
5. Write F# code with `;;` cell boundaries: >fsharp
     let x = 42;;

     let greet name =
       sprintf "Hello, %s!" name;;
<
6. Press `<Alt-Enter>` with cursor in a cell to evaluate it.

7. See inline results appear next to your code.

Run `:checkhealth sagefs` to verify your setup.

3. CELL EVALUATION                                           *sagefs-cells*

Cells are delimited by `;;` at the end of a line. The `;;` marker must
appear at the end of a line (not inside strings or comments).

Example buffer: >fsharp
  let x = 42;;           ← Cell 1

  let y = x + 1;;        ← Cell 2

  printfn "%d" y;;       ← Cell 3
<
When you evaluate a cell (|:SageFsEval| or `<A-CR>`), the plugin:

1. Finds the cell boundaries around your cursor
2. Sends the code to the SageFs daemon via HTTP POST
3. Shows inline results as virtual text (success → green, error → red)
4. Tracks cell state: idle → running → success/error
5. Marks results as stale when you edit the cell

Where results appear:                                      *sagefs-results*

A result is always drawn on a line of its cell that is on screen. The old
rule, "on the cell's last line", put the result off screen whenever the
cell was taller than the window.

- A one-line result is ghost text at the end of the line.
- A longer result goes under the cell's last line when that line is on
  screen and has room for four result lines and the footer. Otherwise it goes under the
  line you evaluated from (or the highest visible line of the cell).
- What does not fit is cut. The last row reads
  `… N more lines, <leader>rE to expand`; |:SageFsResult| (or
  `<leader>rE`) opens the whole result in a float.
- Long lines wrap at the window edge. The one-line summary is cut to the
  room its line has left.
- Evaluating from the last row of the window scrolls the view by the few
  rows it takes to show the result, never past the line you evaluated from.
  Scrolling or resizing later re-places results; it never moves your view.

A result belongs to the buffer you evaluated in. Cell state is one slot per
cell number, so two buffers that both evaluate their cell 1 share a slot;
the later one owns it.

In a file without `;;` (inferred mode), a `///` doc comment belongs to the
declaration below it. A result is never drawn on the next declaration's doc
comment.

When an eval has no result yet:                            *sagefs-pending*

After 4 seconds without a result (`EVAL_SLOW_AFTER_MS` in
`lua/sagefs/config.lua`) the running cell says why, from what the daemon
reports about the session the eval went to, and refreshes every 3 seconds
(`EVAL_STATUS_POLL_MS`):

  still running            session Ready, code still evaluating
  session still warming    Starting, Building, Restarting or WarmingUp
  daemon not reachable     the plugin cannot reach the configured port
  session X faulted: ...   the daemon faulted it, with its reason
  no session attached      nothing is attached to this buffer

Everything but "still running" is also sent to the message line once.
|:SageFsCancel| stops a running eval.

Cell highlight styles (`:SageFsCellStyle` to set or cycle):        *sagefs-cell-style*

- `off`:     No cell highlighting
- `minimal`: Thin `▎` bar in sign column only
- `normal`:  `╭│╰` bracket in sign column (default). Single-line: `◆`
- `full`:    Bracket + EOL line count text + subtle line background

Eval-state feedback: bar color changes during evaluation:
- Blue (idle) → Yellow (running) → Green (success) / Red (error)
- Success fades after 1.5s, error after 3s

Two-mode cell detection:                                *sagefs-cell-modes*

1. **Explicit mode**: `;;` at end of line defines cell boundaries (standard
   F# Interactive syntax). The plugin lexes boundaries, respecting strings
   and comments.

2. **Inferred mode**: Files without `;;` use tree-sitter to detect the
   top-level declaration under the cursor (let bindings, type definitions).
   Each declaration is a separate cell. A `///` doc comment above a
   declaration is part of that declaration's cell.

4. COMMANDS                                              *sagefs-commands*

Connection ~

:SageFsConnect                                          *:SageFsConnect*
    Connect to a running SageFs daemon on the configured port.

:SageFsStart                                            *:SageFsStart*
    Auto-discover .sln/.fsproj in the working directory and start
    the SageFs daemon if not already running. It checks that the
    `sagefs` binary can be found first. If it cannot, the message says
    to run `dotnet tool install --global sagefs` or to set `sagefs_path`
    (see |sagefs-config|).

:SageFsDisconnect                                       *:SageFsDisconnect*
    Disconnect from the SageFs daemon.

Evaluation ~

:SageFsEval                                             *:SageFsEval*
    Evaluate the cell under the cursor. Results appear as inline
    virtual text.

:SageFsEvalAdvance                                   *:SageFsEvalAdvance*
    Evaluate the current cell and move the cursor to the next cell.

:SageFsResult                                           *:SageFsResult*
    Open the full result of the cell under the cursor in a floating window
    (wrapped, `q` closes it). This is what the "N more lines, <leader>rE to
    expand" row under a cut result points at. See |sagefs-results|.

:SageFsHelp                                             *:SageFsHelp*
    List every :SageFs* command with its description, and the SageFs
    keymaps in the current buffer. The list is read from the registered
    command table each time you run it, so it cannot drift from what
    exists. `:Sage<Tab>` completes the same names. See |sagefs-hint|.

:SageFsClear                                            *:SageFsClear*
    Clear all inline results and cell state for the current buffer.

:SageFsCancel                                           *:SageFsCancel*
    Cancel a running evaluation.

Testing ~

:SageFsTestPanel                                        *:SageFsTestPanel*
    Open the live test panel showing pass/fail state.

:SageFsTests                                            *:SageFsTests*
    Show test results in a floating window.

:SageFsRunTests                                         *:SageFsRunTests*
    Trigger a test run for the current session.

:SageFsFailures                                         *:SageFsFailures*
    Jump to failing tests.

:SageFsPickTest                                         *:SageFsPickTest*
    Fuzzy-search all tests by name using telescope.nvim. Each entry shows
    the test status prefix ([PASS]/[FAIL]/[STALE]/[RUN ]/…) and display
    name. Sorted by failure priority. Requires telescope.nvim.
    - <CR>    run the selected test (posts its name as pattern filter)
    - <C-r>   run all tests matching the current prompt query

:SageFsEnableTesting                                    *:SageFsEnableTesting*
    Enable live testing (tests run automatically on hot reload).

:SageFsDisableTesting                                   *:SageFsDisableTesting*
    Disable live testing.

:SageFsDebugTest [name or id]                           *:SageFsDebugTest*
    Debug a failing test with nvim-dap. With no argument it debugs the
    failing test on the cursor line, or the only failing test in the file,
    and asks which one when several fail on the line. With an argument it
    takes a test id or a name pattern. See |sagefs-debug-test|.

:SageFsDebugRelease                                     *:SageFsDebugRelease*
    Release the test SageFs is holding for the debugger and stop the debug
    run. Without nvim-dap this is how you let the test run once you have
    attached a debugger by hand.

Sessions ~

:SageFsSessions                                         *:SageFsSessions*
    List active SageFs sessions. Provides create/switch/stop/reset
    actions from the picker.

:SageFsCreateSession                                    *:SageFsCreateSession*
    Create a new SageFs session for a project.

:SageFsRunApp                                           *:SageFsRunApp*
    Run the active session's application, or the project named as the
    optional argument. The app runs the session's code, so a reload patches
    it live. See |sagefs-repl-behind|.

:SageFsStopApp                                          *:SageFsStopApp*
    Stop the application |:SageFsRunApp| started.

:SageFsWorkflow [name]                                  *:SageFsWorkflow*
    Switch the active session's workflow: `interactive` (REPL),
    `livetesting` or `hotreload`, completed with <Tab>. With no name it
    opens a picker that marks the current one. The daemon restarts the same
    session in place, so the session id stays valid and its REPL bindings
    are not kept, and the command says so as it sends. The daemon accepts
    its own aliases too (`repl`, `live`, `test`, ...), and an unknown name
    comes back in its words with the valid values. The new workflow shows in
    the statusline when the session is ready again.

:SageFsConfig                                           *:SageFsConfig*
    Create or open .SageFs/config.fsx for the current directory.
    Use this to set `AutoOpenNamespaces = false` and disable warmup
    namespace/module auto-open without overwriting an existing config.

Utilities ~

:SageFsStats                                            *:SageFsStats*
    Show runtime statistics: eval count, latency, SSE events,
    reconnects, cells tracked.

:SageFsDashboard                                        *:SageFsDashboard*
    Toggle the floating SageFs dashboard: session, health, tests, coverage,
    hot reload, alarms and the other sections.

:SageFsPlayground                                       *:SageFsPlayground*
    Open a fresh F# scratch buffer with auto-session. Zero-config
    way to start experimenting.

Analysis ~

:SageFsTimeline                                         *:SageFsTimeline*
    Show eval timeline as an ASCII flame chart in a float window.
    Each bar represents an evaluation, with width proportional to
    duration. Error evals use a different marker.

:SageFsDiff                                             *:SageFsDiff*
    Show the diff between the last two evaluations of the cell
    under the cursor. Highlights changed, added, and removed lines.

:SageFsScopeMap                                         *:SageFsScopeMap*
    Show a binding scope map - which F# bindings are live at each
    point in the file, which cells defined them, and whether
    they've been shadowed.

:SageFsNotebook [file]                                  *:SageFsNotebook*
    Export the full session as a literate .fsx notebook. Metadata
    (timing, bindings, status) is stored in F# block comments,

:SageFsArrows                                           *:SageFsArrows*

:SageFsHistory                                          *:SageFsHistory*

:SageFsTypeFlow                                         *:SageFsTypeFlow*

:SageFsExport                                           *:SageFsExport*
    Export the current session as an .fsx file.

:SageFsTypeExplorer                                     *:SageFsTypeExplorer*

:SageFsTestTrace                                        *:SageFsTestTrace*
    Show the current test trace state.

:SageFsStatus                                           *:SageFsStatus*
    Show connection status and session information, including a "Source:"

:SageFsCellStyle [style]                                *:SageFsCellStyle*
    Set cell highlight style, or cycle if no argument given.
    Styles: off, minimal, normal, full. See |sagefs-cell-style|.

:SageFsEvalFile                                         *:SageFsEvalFile*
    Evaluate the entire file.

:SageFsEvalLine                                         *:SageFsEvalLine*
    Evaluate only the current line (not the enclosing cell).

:SageFsBindings                                         *:SageFsBindings*

:SageFsExportFile                                       *:SageFsExportFile*

:SageFsCallers {symbol}                                 *:SageFsCallers*

:SageFsStop                                             *:SageFsStop*
    Stop the managed SageFs daemon.

:SageFsSwitchProject                                    *:SageFsSwitchProject*
    Re-scan for .fsproj/.sln/.slnx files and let the user pick which

:SageFsReset                                            *:SageFsReset*
    Soft reset active FSI session.

    Hard reset (rebuild) active FSI session. The daemon rebuilds in the

:SageFsContext                                          *:SageFsContext*
    Show session context (assemblies, namespaces, warmup).

:SageFsLoadScript {file}                                *:SageFsLoadScript*
    Load an `.fsx` script file via `#load`.

:SageFsCoverage                                         *:SageFsCoverage*
    Show coverage summary with per-file breakdown.

:SageFsCoveringTests                                     *:SageFsCoveringTests*
    Float at the cursor with the tests that cover this line (name and last
    result). <CR> jumps to a test. See |sagefs-covering-tests|.

:SageFsTestPolicy                                       *:SageFsTestPolicy*
    Configure test run policies per category.

:SageFsTestsHere                                        *:SageFsTestsHere*
    Show tests for the current file.

:SageFsHotReload                                        *:SageFsHotReload*
    Hot reload file picker.

:SageFsWatchAll                                         *:SageFsWatchAll*
    Watch all files for hot reload.

:SageFsUnwatchAll                                       *:SageFsUnwatchAll*
    Unwatch all files for hot reload.

:[count]SageFsNudge [up|down [step]|set [value]|expr [expression]|undo|redo|list]
                                                             *:SageFsNudge*
    Change one value in the file you are in, through the daemon, without
    typing it: |:SageFsNudge| up bumps the number under the cursor by one
    step (a count repeats it), down lowers it, set takes a literal, expr an
    F# expression, undo and redo step through what was written, and list
    shows every value of the file. With no argument it bumps up. The daemon
    writes the file, so a buffer with unsaved edits is refused. See
    |sagefs-nudge|.

:SageFsReloadStatus                                   *:SageFsReloadStatus*
    Show what the last save did to the running app, how it got there
    (detour or metadata delta), the named causes and the remedy, and whether
    the REPL is behind the app, and whether the build is behind the files on
    disk (naming the changed files and the fix). See |sagefs-hotreload|.

:SageFsCohort                                               *:SageFsCohort*
    Show the daemon's cohort in a scratch buffer: members, claims, the
    landing queue, the integration session and the trunk lines. It reads
    the MCP tool `get_cohort_status`, refreshes when a cohort event or a
    reload report arrives. A member id `mcp:m-<hex>` or `cap:<hex>` is shown
    whole; an older daemon's `mcp:` session id is cut to six characters.
    `q` closes the buffer, `r` refreshes it.
    See |sagefs-cohort|.

:SageFsMintMember {role} [scope] [minutes]              *:SageFsMintMember*
    Mint a cohort member token with the daemon's `mint_member` tool and
    show it once in a float. {role} is Observer, Analysis, Verifier or
    Implementer (completed with <Tab>). [scope] is a repo-relative
    directory prefix; empty or `.` means the whole repo. [minutes] is 0 to
    480; 0 means the daemon's default of 120. The token is shown in a
    scratch buffer with no swap file and no undo, closed by `q` or by
    leaving the window. It is never passed to |vim.notify()|, so it is not
    in |:messages|, and the command line holds no token, so it is not in
    the command history. Only the cohort's conductor may mint, and the
    plugin's own MCP connection is the conductor only if it joined first.
    Anyone else gets the daemon's refusal. See |sagefs-member-token|.

:SageFsRevokeMember {cap:id}                           *:SageFsRevokeMember*
    Revoke a minted member with the daemon's `revoke_member` tool. {cap:id}
    is the `cap:<hex>` id shown by |:SageFsCohort| or by the mint reply. The
    token is refused from the next call, for ever. Conductor only.
    See |sagefs-member-token|.

:SageFsHygiene                                             *:SageFsHygiene*
    Show what agents and orchestrators left behind on this machine
    (worktrees, branches, gate checkouts) as the daemon's dry-run plan:
    what is safe to reclaim, what needs a look, what is in use, and the
    command that saves each one. It reads the MCP tool
    `get_workspace_hygiene` and never calls `tidy_workspace`, because
    reclaiming deletes other people's worktrees and a keystroke in an
    editor is not that decision. `q` closes the window, `r` reads the plan
    again. An older daemon's answer is shown in its own words with a note.

5. KEYMAPS                                               *sagefs-keymaps*

Always-on keymaps (global, not buffer-local): >

  <A-CR>       (n) Evaluate cell under cursor (smart: prompts for session)
  <A-CR>       (v) Evaluate visual selection
  <S-A-CR>     (n) Evaluate cell and advance to next cell
<
The `<leader>r` namespace is used for all REPL bindings (**R**EPL prefix).
All leader keymaps are registered globally via `setup()`.

Core eval ~
>
  <leader>re   Evaluate cell under cursor
  <leader>rl   Evaluate current line
  <leader>rf   Evaluate entire file
  <leader>rE   Open the full result of the cell under the cursor (float)
  <leader>rc   Clear all results
  <leader>rx   Cancel running evaluation
<
Sessions & connection ~
>
  <leader>rs   Session picker (create/switch/stop/reset)
  <leader>rC   Connect SSE stream
  <leader>rX   Disconnect SSE stream
  <leader>ri   Status info dashboard
<
Testing ~
>
  <leader>rt   Test panel (toggle persistent split)
  <leader>rT   Run tests
  <leader>rth  Tests here (current file)
  <leader>rtf  Test failures
  <leader>rtp  Test trace (three-speed pipeline state)
  <leader>rte  Enable live testing
  <leader>rtd  Disable live testing
  <leader>rtg  Debug the failing test on this line (nvim-dap)
  D            Debug the test on this row (inside the test panel)
  <leader>rtc  Tests that cover this line (float, <CR> jumps)
  <leader>tf   Filter tests by name pattern (prompts for input)
  <leader>tF   Run all tests (clears any active filter)
  <leader>tp   Fuzzy-pick and run a test (telescope, SageFsPickTest)
<
Browse & explore ~
>
  <leader>rb   Live bindings pane
  <leader>rd   Eval diff (last two evals of current cell)
  <leader>rg   Scope map (what each cell defines)
  <leader>rm   Timeline (flame chart of eval history)
  <leader>ry   Type explorer (namespace drill-down)
  <leader>ra   Callers of symbol
  <leader>ro   Callees of symbol
  <leader>rv   Coverage summary
<
Server & reload ~
>
  <leader>rh   Hot reload file picker
  <leader>rr   Soft reset FSI session
  <leader>rR   Hard reset (rebuild) FSI session
  <leader>rS   Start SageFs daemon
  <leader>rQ   Stop SageFs daemon
  <leader>rD   Cycle display density (minimal → normal → full)
<
Misc ~
>
  <leader>rp   Playground (scratch F# buffer)
  <leader>rn   Notebook export
  <leader>rw   Watch all files for hot reload
  <leader>rW   Unwatch all files
<
Nudge a value ~
>
  <leader>rk+  Bump the number under the cursor up (a count repeats: 5<leader>rk+)
  <leader>rk-  Bump it down
  <leader>rks  Set it to a typed literal
  <leader>rke  Replace it with an F# expression
  <leader>rku  Undo the last nudge in this file
  <leader>rkr  Redo it
  <leader>rkl  List the values of this file and nudge one
  <A-k>        Scrub up: one nudge per press; hold the key to repeat it and
               the value turns like a knob (remap: SCRUB_UP_KEY in config)
  <A-j>        Scrub down (remap: SCRUB_DOWN_KEY in config)
<

6. CONFIGURATION                                         *sagefs-config*

Pass configuration to setup(): >lua

  require("sagefs").setup({
    port = 37749,                -- SageFs daemon port
    dashboard_port = 37750,      -- Dashboard/hot-reload port
    sagefs_path = "sagefs",      -- Binary |:SageFsStart| runs (full path if
                                 -- PATH does not see it; ~ and $VAR expand)
    session_refresh_debounce_ms = 250, -- Burst of "session ready" events
                                       -- makes one session-list refresh
    auto_connect = true,         -- Connect on F# file open
    check_on_save = false,       -- Run type check on save
    notify_reload = true,        -- vim.notify when a save needs attention
    density = "normal",          -- "minimal" | "normal" | "full"
    hint = true,                 -- One-time first-run hint (see |sagefs-hint|)
    member_token = nil,          -- Cohort member token (see |sagefs-member-token|)
    cell_highlight = {
      style = "normal",          -- "off" | "minimal" | "normal" | "full"
      flash_duration_ms = 300,   -- Flash fade duration
    },
  })
<
First-run hint:                                              *sagefs-hint*

The first time the plugin attaches to an F# buffer it shows a small float
with the three commands I would learn first (evaluate, sessions, help) and
says that `:Sage<Tab>` completes the rest. Any cursor move dismisses it. A
marker file, `sagefs_hint_seen` under `stdpath("data")`, keeps it from
coming back. `hint = false` turns it off; `hint_marker_path` moves the
marker file.

Density presets control information density: ~

  minimal:  Results only, no type hints, no timing
  normal:   Results + timing + type hints for top-level bindings
  full:     Everything - all type hints, shadows, diagnostics

                                                       *sagefs-member-token*
Member token: ~

A daemon that mints per-run member tokens (the `mint_member` tool) gives
each token its own cohort member (`cap:<hex>`), role, scope and expiry. To
run the plugin as one, set `member_token = "sfm_..."` in setup(), or set
the `SAGEFS_MEMBER_TOKEN` environment variable before Neovim starts. The
option wins when both are set. The plugin sends the token as the
`X-SageFs-Member-Token` header on every MCP request it makes (the
|:SageFsCohort| view). With no token configured it sends no header.

The token is never printed. Failure texts are scrubbed, the debug log
(`vim.g.sagefs_debug`) shows the header as (hidden), and |:checkhealth|
says `member_token = set (hidden)`. SageFs keeps only a token's hash, so a
leaked token cannot be taken back, only revoked.

|:SageFsMintMember| and |:SageFsRevokeMember| mint and revoke tokens from
the editor. A token is shown once, in a float, and nowhere else.

7. LIVE TESTING                                          *sagefs-testing*

SageFs provides a three-speed live testing pipeline (timings are design
goals - the engine's own docs cite 300–800ms typical on the hot path):

1. Tree-sitter detects tests in ~50ms (even in broken code)
2. F# Compiler Service builds dependency graph in ~350ms
3. Affected tests execute in ~500ms total

The plugin shows test results as gutter signs: >

  ✓  Test passed (green)
  ✗  Test failed (red)
  ●  Test running (yellow)
  ◌  Test discovered but not yet run
<
Commands: |:SageFsTestPanel|, |:SageFsRunTests|, |:SageFsEnableTesting|

------------------------------------------------------------------------------
7.1 Debugging a failing test                              *sagefs-debug-test*

A test runs in the process that loaded your code, so debugging it means
attaching a .NET debugger to that process. Put the cursor on a line that
shows the "debug" hint (end of line, drawn for every failing test) and
press <leader>rtg, or run |:SageFsDebugTest|. With the cursor on a line that
has no failing test, the one failing test of the file is named and you are
asked before it is held. The hint is drawn only when the display density
allows it (minimal draws none). <leader>rtD is not used: it sits one shifted
letter from <leader>rtd, which disables live testing.

In the test panel (|:SageFsTestPanel|), D on a test row debugs that test: the
row carries the test id, so nothing is asked. That run is tied to no buffer,
so closing the panel does not end the hold.

|:checkhealth| sagefs says whether nvim-dap is there, which coreclr adapter
it would use (yours, or netcoredbg on PATH or under mason) and, on Linux,
what kernel.yama.ptrace_scope is. A missing piece is information or a
warning with the way to fix it, never an error: the plugin and every other
feature work without nvim-dap.

The plugin asks the daemon to hold the test (POST /api/live-testing/debug),
attaches the coreclr adapter through nvim-dap to the pid it answers, then
releases the test (POST /api/live-testing/debug/continue) once the attach
has finished and keeps asking while the daemon answers still_running. When
the test finishes it detaches without killing the host and shows the result.

The adapter is checked before anything is held. A `dap.adapters.coreclr` you
configured is used as it is. Otherwise netcoredbg is looked for on PATH and
under the mason directory. Nothing is ever installed. If it is missing, the
message says what to install and no test is held.

A test is not left held behind a debugger that is gone. The hold is released
when the debug session ends, when dap.run fails, when the adapter dies or
never starts (a session of ours is looked for 5 seconds after dap.run), when
the buffer you started from is deleted (also while the daemon is still
answering the hold request) and when Neovim exits. If you quit before the
daemon answered the hold, the answer is waited for up to 2 seconds and
released before Neovim goes. The backstop is the two minute hold window.

Four cases wait for that backstop: an adapter that starts and never answers
initialize, a Neovim that is killed instead of quit, a daemon that takes
longer than 2 seconds to answer a hold you quit on, and a daemon that cannot
be reached while releasing (the release is tried twice, one second apart, and
the message says the test may stay held for up to two minutes).

nvim-dap is optional. Without it the test is still held, the pid and the
instruction "attach to process N" are printed, and |:SageFsDebugRelease|
lets the test run once you are attached.

Breakpoints bind in your project's compiled assemblies. A test file SageFs
re-evaluated after a save has no PDB, so hard reset the session with a
rebuild to debug the compiled copy. On Linux, kernel.yama.ptrace_scope at 1
works (the host opens the door for the length of the hold); at 2 or 3 the
attach is refused.

7.2 Live bindings                                         *sagefs-bindings*

|:SageFsBindings| (<leader>rb) opens a split with the value tree the daemon
walks for the session. It is updated from the daemon's live_bindings
snapshots, which arrive after every eval, every click and every mode switch.

Some members are held back, and every held row says why, in the daemon's
words:
- A getter that calls other code or loops shows "not evaluated: ..." and
  [<CR> run]. <CR> on it runs that one getter on the daemon, on its own
  thread with a 5 second deadline and, on Linux x86-64, under a syscall
  filter (no network, no file writes, no new processes). The line under the
  header says what protected the run, as the daemon wrote it. It does not
  stop a spin, a stack overflow or an in-memory effect. While the getter
  runs the pane says "running <binding>.<member>" under the header, a second
  <CR> waits for the first to answer (a getter that spins takes about ten
  seconds), and the cursor stays on its row when the lines above it change.
  A long containment line is split at its own semicolons, one piece per
  line.
- A getter you ran that timed out, threw or could not be contained shows
  "unknown" and the reason.
- A lazy sequence is never enumerated for you.

Pane keys: >
  <CR>   run the getter on this row
  <Tab>  fold or unfold
  m      walk mode: Safe, Everything, Off
  r      ask the daemon for the current snapshot
  q      close
<
Walk modes:
  Safe        Reads fields and runs only getters that provably do nothing.
              Every other getter is listed and runs only when you click it.
  Everything  Runs your getters: every public property of every class value,
              after every eval. That is your code running, and it can take
              time or change things. The plugin asks before switching to it.
  Off         Does not open class instances. Records, unions, tuples, lists
              and maps still show.

The daemon has no call that returns the current snapshot, it only pushes one.
"r", and opening the pane with nothing folded yet, re-post the current mode,
which makes the daemon walk again and push. That also drops the containment
line of the last click.

Commands: |:SageFsBindings|, |:SageFsBindingList|

  ┃  Line covered (green)
  ┃  Line not covered (red)
  ┃  Line partially covered (yellow)

8.1 Which tests cover a line                             *sagefs-covering-tests*

The daemon records coverage per test. On every covered line, the
file_annotations event lists exactly the tests whose own recorded coverage
reaches it. |:SageFsCoveringTests| (<leader>rtc) opens a float at the cursor
with those tests, each with its last result. <CR> on a test jumps to it, q
closes. When the daemon marked the line covered but sent no per-test reading,
the float says so.

Per symbol, the coverage_view event sends one badge (for example "✓ 97 ✗ 3",
with "+N more" when some did not fit). It is drawn at the end of the symbol's
definition line, colored by health, and follows |sagefs-config| density
(minimal turns it off).

coverage_view events are merged per file and run generation. A newer
generation replaces the file's whole set, the same generation adds one badge
per symbol, an older generation is dropped as a straggler, and an event with
no generation counts as 0 and never replaces anything.

The older per-batch coverage_updated events are folded as before.

9. SESSIONS                                              *sagefs-sessions*

SageFs supports multiple simultaneous sessions across different projects.
Each session runs in an isolated FSI worker process.

Use |:SageFsSessions| to list sessions and switch the active one from its
picker, and |:SageFsCreateSession| to start a new one.

Which session an eval goes to:                      *sagefs-session-routing*

An eval goes to the session whose working directory holds the file you are
editing. A git worktree is its own directory: the main checkout's session is
not used for a worktree nested under it, even though the paths nest.

If no session matches, nothing is sent. The plugin says so, lists the
sessions that exist (project, short id, status, the tail of the directory),
and offers to create a session for this directory (you pick the project; the
plugin never guesses one) or to evaluate in a named session. That pick is
remembered for the directory. The same check runs at startup, so a daemon
that already has other sessions still gets the offer.

|:SageFsStatus| has an "Eval here:" line naming the session an eval from the
current buffer would reach. The |:SageFsSessions| picker shows each
session's directory and short id.

Warmup, fault and ready events of other sessions on a shared daemon are
ignored; only your session's reach the message line.

10. HOT RELOAD                                           *sagefs-hotreload*

When you save an .fs file, SageFs hot-reloads the change in ~100ms using
Harmony runtime patching. The plugin shows hot reload status and can
trigger manual reloads.

                                                        *sagefs-reload-truth*
What the last save did ~

The daemon reports what each save did to the running app. The plugin turns
that report into words in one place (`lua/sagefs/reload_state.lua`), and the
statusline, a virtual-text mark on the first line of the saved file,
|:SageFsReloadStatus| and the dashboard's hot reload section all use it: >

  PatchPending      applied, new body has not run yet
  Patched           patched (ran)
  NeverEntered      applied, but the new body never ran (N of M did)
  Restarted         restarted: <cause>
  RestartRequired   restart needed: <cause>
  CompileFailed     did not compile; the app keeps running the last code
                    that did
  NoEffect          no effect (N of M changed definitions reached the app)
  KeptLiveState     kept live value
<
A patch is applied first and patched once its new body has been seen
running, so a pending patch is never shown as live. The mechanism is read
from the report's `mechanism` field: `detour` shows as `[detour]` and
`metadata-delta` as `[delta]` in the statusline. A verdict or mechanism the
plugin does not know is shown as unrecognized.

The statusline keeps pending, never-ran, restart and compile-failed states
until the next save replaces them. Patched and kept fade after 15 seconds,
no-effect after 8. With `notify_reload` on, a never-ran patch, a restart and
a compile failure also call |vim.notify|.

The cause of a restart is the first line of the report's `message`. The
closed cause names (`FieldsChanged`, `MetadataDeltaUnavailable`, ...) are in
the worker's own payload as `reasons`; the plugin reads them when a payload
has them.

                                                       *sagefs-repl-behind*
The REPL can be behind the app ~

After a metadata delta is patched into an app that |:SageFsRunApp| started,
the app runs the new code and the REPL keeps the build from before it. The
daemon reports this as `replFreshness`: `InSync`, or `BehindApp` with the
number of saves and the declarations. The plugin shows `REPL BEHIND app` in
the statusline and says it once in a line when you eval: >

  The REPL is BEHIND the app (1 save: Handlers.describe): calls to what
  changed run the OLD code. :SageFsHardReset rebuilds the REPL and stops the
  running app (:SageFsRunApp starts it again).
<
|:SageFsHardReset| replaces the worker, so the running app stops with it.
The daemon's `WARNING: The REPL is BEHIND the app` line after an eval result
is taken off the cell output and shown as that message. The message repeats
after a minute, or at once when the state changes.

                                                            *sagefs-cohort*
The cohort and the trunk ~

|:SageFsCohort| reads `get_cohort_status` over MCP, since it has no REST
route. The trunk section shows one `trunk <landingId>: ...` line per landing
in the same words as above. A trunk line changes from applied to patched
with no cohort event, so the buffer also refreshes on every reload report.
A member id is `mcp:m-<16 hex>` (a connection's fingerprint), `cap:<hex>` (a
run minted with `mint_member`, marked `(minted run)`) or, from a daemon older
than member tokens, `mcp:` plus the agent's MCP session id. The first two are
shown whole. The third works as a bearer handle, so only its first six
characters are shown.

                                                              *sagefs-nudge*
Nudging a value ~

The daemon's `nudge_value` tool changes ONE value in a source file the
session owns and writes the file as just that expression. The running app
picks the change up through hot reload when it is watching the file (the
reply says so when it is not: |:SageFsWatchAll|). |:SageFsNudge| puts it
under the cursor: >vim

  :SageFsNudge up          " 12.5 -> 12.6 (the step is the last decimal place)
  :5SageFsNudge down       " five steps down
  :SageFsNudge up 0.25     " a step of your own
  :SageFsNudge set 13.5    " a typed literal, read as the kind it already is
  :SageFsNudge expr gravity * 2.0
  :SageFsNudge undo
  :SageFsNudge redo
  :SageFsNudge list        " every value of the file, pick one, type its value
<
The same under <leader>rk (+ - s e u r l), and a count repeats a bump.
The scrub keys <A-k> and <A-j> run this same flow once per press, so a
held key lands step after step, in order, through the same door (the
terminal or GUI repeats the key; a <leader> sequence cannot be held,
because auto-repeat repeats only its last key). Each press is its own
journaled write with its own undo. Remap them by setting SCRUB_UP_KEY
/ SCRUB_DOWN_KEY of sagefs.config before an F# buffer attaches; they
are buffer-local maps, so a map of your own over them works too.
A bool toggles. An integer goes by one. Hex goes up as the number it is and
is written back in hex; a unit of measure (12.5<m/s>) is kept. A union case
or any other expression is set with set or expr, not bumped.

How it goes: the plugin inspects the file, finds the listed value that is
under the cursor, and sets it with the hash inspect gave. A value that
changed since is refused by the daemon and nothing is written. The daemon
sends each value's range (line, column, end line, end column, columns in
characters), and the plugin turns the cursor's byte column into the same
count, so the value is the one whose range holds the cursor: two values with
the same text on one line are two ranges, and a value that spans lines is
found from any line it covers. When a value sits inside a bigger one, you are
asked which; the plugin never guesses.

The daemon writes the file on disk, so:
  - a buffer with unsaved edits is refused by name (write it, or :edit! to
    drop the edits), and a buffer that is no file is refused;
  - a buffer that changed while the daemon was answering is not written to;
  - after a write, undo or redo the buffer is read again, and the cursor
    stays where it was. A buffer you started editing since is left alone;
  - one nudge runs at a time per buffer and the rest wait in order (up to
    20), so a held key lands every step instead of being refused.

A refusal is shown as the daemon says it: its token, its rule and its next
action. Every call names the session by its working directory (the active
session's own), because the daemon will not guess when several sessions
share one.

                                                          *sagefs-versions*
Versions ~

The plugin's version always matches the SageFs release it was tested
against: SageFs 0.6.875 goes with sagefs.nvim 0.6.875. `sync-version.sh`
(or `sync-version.ps1`) copies the number from SageFs's
`Directory.Build.props` into `lua/sagefs/version.lua`.

Whether the plugin and a daemon can talk is a separate question that the
release number does not answer. The daemon reports an integer `apiVersion`
on /health and /version, and the plugin declares the range it understands
in `lua/sagefs/compat.lua` (api 3 today), with a reason for each bound.

  Same api version      `:checkhealth` says "compatible".
  Api outside the range `:checkhealth` reports an error naming both numbers
                        and which side to update (the plugin, or the daemon
                        with `dotnet tool update --global sagefs`), and you
                        get one warning at startup. Only this case warns.
  Different release     A quiet info line in `:checkhealth`, for example
  numbers, same api     "plugin 0.6.875, daemon 0.6.880: update the plugin
                        when you can". No startup warning.

14. CELL HIGHLIGHT                                       *sagefs-cell-highlight*

The cell highlight system shows which region of code will be sent to SageFs
when you press `<A-CR>`. It adapts to transparent terminals.

Styles ~

  `off`       No cell highlighting
  `minimal`   Thin `▎` bar in the sign column
  `normal`    `╭│╰` bracket in the sign column (default)
  `full`      Bracket + EOL line count + subtle line background

Use |:SageFsCellStyle| to set or cycle styles.

Eval-state feedback ~

The sign column bracket changes color during evaluation:

  Blue    Idle/neutral
  Yellow  Evaluation running
  Green   Success (fades after 1.5s)
  Red     Error (fades after 3s)

Highlight groups (all overridable): >

  SageFsCellBar          Sign column bar (neutral)
  SageFsCellBarRunning   Sign bar during eval
  SageFsCellBarSuccess   Sign bar on success
  SageFsCellBarError     Sign bar on error
  SageFsCellBound        Boundary markers and line counts
  SageFsCellLineFull     Full-mode line background
  SageFsCellNumber       Line number tint
<
Transparency support ~

On transparent terminals (no `Normal` bg), the `full` mode uses
`underdouble` instead of a background color. The `normal` mode uses
zero background by design - just sign column characters.

15. USER AUTOCMD EVENTS                                      *sagefs-events*

sagefs.nvim fires `User` autocmds for all SageFs daemon events. Use these
to build custom integrations or extend the plugin's behavior.

All events carry a `data` table in `vim.v.event`. Listen with: >lua

  vim.api.nvim_create_autocmd("User", {
    pattern = "SageFsEvalCompleted",
    callback = function(ev)
      -- ev.data contains the payload (may be nil for connection events)
      print(vim.inspect(ev.data))
    end,
  })
<

Event reference ~

*SageFsEvalCompleted*
    Fired when an evaluation completes (success or error). Payload contains
    evaluation result data.

*SageFsEvalResult*
    Fired when an eval result is received from the daemon. Payload: >

      { filePath, blockStartLine, output, success }
<
    - `filePath`       Path to the evaluated file
    - `blockStartLine` 1-based line of the cell's start
    - `output`         Result text (stdout/error)
    - `success`        Boolean - true if eval succeeded

    Example: >lua

      vim.api.nvim_create_autocmd("User", {
        pattern = "SageFsEvalResult",
        callback = function(ev)
          if not ev.data.success then
            vim.notify("Eval error: " .. (ev.data.output or ""), vim.log.levels.WARN)
          end
        end,
      })
<

*SageFsEvalHeartbeat*
    Fired about twice a second while an evaluation is running, so an
    integration can show elapsed time and see the stream is alive. Payload: >

      { FilePath, BlockStartLine, ElapsedMs }
<
    - `FilePath`        File being evaluated
    - `BlockStartLine`  1-based line of the cell's start
    - `ElapsedMs`       Milliseconds since the eval started

    Stops when the eval finishes (an eval_result follows); the dashboard's
    Output section shows the elapsed time while it runs.

*SageFsTestPassed*
    Fired when a single test transitions to passed state.

*SageFsTestFailed*
    Fired when a single test transitions to failed state.

*SageFsTestResultsBatch*
    Fired when a batch of test results arrives. More efficient than
    per-test events for bulk updates.

*SageFsTestRunStarted*
    Fired when the daemon begins executing a test run.

*SageFsTestRunCompleted*
    Fired when a test run finishes (all tests resolved).

*SageFsTestState*
    Fired when overall test state changes (e.g., enabled/disabled).

*SageFsTestsDiscovered*
    Fired when the daemon detects new tests in the project.

*SageFsTestSourceLocations*
    Fired when the daemon sends where each test is defined. Payload:
    `Locations`, each with `TestName` and `FilePath`. Used to jump from the
    test panel to the source.

*SageFsFailureNarratives*
    Fired with the daemon's explanation of failing tests. Payload: a list of
    narratives, each with a `TestId`.

*SageFsConnected*
    Fired when the SSE stream successfully connects to the daemon.

*SageFsDisconnected*
    Fired when the SSE stream disconnects.

*SageFsReconnecting*
    Fired when the plugin is retrying a dropped SSE connection
    (exponential backoff: 1s → 2s → 4s → … → 32s).

*SageFsCoverageUpdated*
    Fired when coverage data is updated. Triggers gutter sign refresh.

*SageFsHotReloadTriggered*
    Fired when a hot reload event is received from the daemon.

*SageFsWarmupProgress*
    Fired as a session warms up (creating FSI, scanning sources, loading
    assemblies, finalizing). Payload: `Phase`, `Step`, `Total`, `Message`,
    and a session id. Every session's warmup arrives, so check the id before
    acting on it.

*SageFsWarmupCompleted*
    Fired when a session finishes warming up. Payload: `session_id` and
    `project_count`.

*SageFsSessionFaulted*
    Fired when a session faults, for every session on the daemon. Payload:
    `sessionFaulted` (the session id) and `error`. The plugin only shows a
    message for the session this editor uses.

*SageFsFileReloaded*
    Fired when the daemon reloaded a watched file. Payload: `fileReloaded`
    (the path) and `sessionId`.

*SageFsSystemAlarm*
    Fired when the daemon raises a system alarm. Payload: `phase` and
    `message`. The plugin also shows the message as an error and a warning
    mark in the statusline.

*SageFsWarmupContext*
    Fired when session warmup context data arrives (assemblies, namespaces,
    timing). Used to populate `:SageFsContext`.

*SageFsHotReloadSnapshot*
    Fired with a full hot-reload snapshot (all watched files and their
    watch status).

*SageFsReloadReported*
    Fired with what a save did to the running app: the `reloadReported`
    object (`state`, `outcome`, `mechanism`, `patched`, `considered`,
    `message`, `suggestedAction`) and `sessionId`. A payload with only a
    `sessionId` means the report was cleared.

*SageFsReplFreshnessChanged*
    Fired when a session's REPL freshness is read from the session list.
    Payload: `sessionId` and `freshness` (`state`, `saves_since`,
    `declarations`, `message`).

*SageFsCohortMatrix*
    Fired with the cohort frame: members, claims, landings, integration
    head. One cohort spans every session, so there is no `SessionId`.

*SageFsClaimChanged*
    Fired when a claim is acquired, released, orphaned or reassigned.

*SageFsLandingChanged*
    Fired when a landing changes state (queued, rebasing, verifying,
    blocked, landed, withdrawn).

*SageFsSaveObserved*
    Fired when a cohort member's watcher sees a save inside another
    member's claim. Advisory.

*SageFsCohortChanged*
    Fired when someone joins, leaves, claims, releases or lands.

*SageFsProvidersDetected*
    Fired when the daemon reports which test providers are active
    (xUnit, NUnit, Expecto, etc.).

*SageFsAffectedTestsComputed*
    Fired with the set of tests affected by a code change. Shows which
    tests the three-speed pipeline will execute.

*SageFsTestCycleTimingRecorded*
    Fired with timing data for the three-speed test pipeline waterfall
    (tree-sitter → FCS → execution phases).

*SageFsRunTestsRequested*
    Fired when a test run is requested (before execution starts).

*SageFsTestSummary*
    Fired with an aggregate summary (total/passed/failed/running/stale).
    Used for statusline and panel header.

*SageFsFileAnnotations*
    Fired with per-file annotation data (coverage signs, CodeLens,
    inline failure messages).

*SageFsCoverageView*
    Fired with one per-symbol coverage badge (symbol, definition line, total
    covering tests, one-line badge text, health, run generation).

*SageFsBindingsSnapshot*
    Fired with a snapshot of all active FSI bindings (name → type_sig).
    Used to populate `:SageFsBindings`.

*SageFsLiveBindings*
    Fired with the live bindings snapshot of one session: the whole value
    tree, with the reason for every row that was not evaluated. Used by
    |:SageFsBindings|.

*SageFsTestTrace*
    Fired with three-speed test pipeline trace data. Used to populate
    `:SageFsTestTrace`.

*SageFsTestRecoveryNeeded*
    Fired when the daemon detects a test session that needs recovery
    (e.g., worker crash, stale state).

*SageFsEvalDiff*
    Fired with the diff between the last two evaluations of a cell.

*SageFsCellDependencies*
    Fired with dependency graph data for the current buffer's cells.

*SageFsBindingScopeMap*
    Fired with binding scope map data (what each cell defines, shadows).

*SageFsEvalTimeline*
    Fired with evaluation timeline data (timestamps, durations, status).

16. FAQ                                                      *sagefs-faq*

Q: How do I install SageFs?
A: `dotnet tool install --global sagefs`. See the SageFs README for details.
   If |:SageFsStart| says `sagefs` is not on PATH, restart Neovim after
   installing so it sees the new PATH, or set `sagefs_path` to the full
   path of the binary.

Q: How do I start the daemon?
A: Run `sagefs --proj YourApp.fsproj` in a terminal, or use |:SageFsStart|
   which auto-discovers projects in the working directory.

Q: Can I use this with multiple projects?
A: Yes. SageFs supports multiple sessions. Use |:SageFsCreateSession|
   for each project and the |:SageFsSessions| picker to change between them.

Q: What's the `;;` for?
A: `;;` at the end of a line marks a cell boundary. This is standard F#
   Interactive syntax. Cells are the unit of evaluation - press `<A-CR>`
   to evaluate the cell your cursor is in.

Q: I pressed <A-CR> and nothing happened.
A: After 4 seconds the cell says why: still running, session still warming,
   daemon not reachable, session faulted, or no session attached. See
   |sagefs-pending|. If it says no session, see |sagefs-session-routing|.

Q: The result is cut off.
A: The last row says how many lines are left. `<leader>rE` or |:SageFsResult|
   opens all of it. See |sagefs-results|.

Q: What commands are there?
A: |:SageFsHelp|, or type `:Sage<Tab>`.

Q: Results are stale after I edit - how do I refresh?
A: Press `<A-CR>` again to re-evaluate. Results automatically go stale
   (dimmed) when you edit the cell they belong to.

Q: How do I see test results?
A: Use |:SageFsEnableTesting| to turn on live testing, then
   |:SageFsTestPanel| to see the results panel.
